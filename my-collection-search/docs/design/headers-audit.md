The adopted page-header and section-heading decisions are maintained as
implementation conventions in [`../CLAUDE.md`](../CLAUDE.md#ui-conventions).

## Scope and method

There are **22 page routes**, **22 production files calling PageHeader**, **64 raw Chakra Heading sites**, and **4 additional Text/Box h2 sites**, plus **20 hand-built Text subsection sites**. Counts are source sites, not the number of headings produced by loops. PageHeader has multiple state branches in Enrich and genre detail; Tracks also has a suspense fallback. Section wrappers and call sites are listed separately to avoid counting a component definition as every instance it renders.

The required `git ls-files 'my-collection-search/src/app/**/page.tsx'` lists 21 nested pages. `src/app/page.tsx` adds Home. Each was followed through its rendered view. Searches used tracked-file lists, including `git ls-files | xargs grep`, then the redesigned Home, Spins and Chores structures were read for headings implemented as Text/Box. Per-record row titles, metric values and action labels are content rather than section headings. Queue and spin-detail panels are included; dialogs get a reference only.

All file locations below are relative to `my-collection-search/src/`. Typography comes from `app/chakraTheme.ts`, `app/houseStyle.ts:78`, `app/fontChoices.ts` and the installed Chakra heading/text-style recipes, not the numeric-looking `size` name alone.

## Theme resolution

- `heading`: user-selected display face, default **IBM Plex Sans**; `body`: user-selected body face, also Plex Sans by default; `label`: user-selected labels face, default **IBM Plex Mono**. **`mono` is fixed Plex Mono**, unaffected by the label selector. Fallbacks are Helvetica Neue/Arial for display/body and ui-monospace/SFMono-Regular/Menlo/Consolas for labels/mono.
- Chakra Heading defaults to `h2`, `heading`, **600**, `size="xl"`: **20px / 30px**. Explicit `fontSize` changes the size but leaves that 30px line height unless explicitly overridden. `size="sm"` = **14/20**, `md` = **16/24**, `lg` = **18/28**, `xl` = **20/30**, `2xl` = **24/32**. Weight names: normal 400, medium 500, semibold 600, bold 700. Default casing is unchanged and default letter spacing is normal.
- Space units are 4px: `1` 4px, `1.5` 6px, `2` 8px, `2.5` 10px, `3` 12px, `3.5` 14px, `4` 16px, `5` 20px, `6` 24px, `7` 28px, `8` 32px, `10` 40px. `outline` is **2px**, `rule` **1px**. All normal radius tokens resolve to zero. Hard shadows `sm`/`md` offset 3px/6px, no blur.
- Semantic colors are palette CSS variables: `bg` ground, `fg` ink, `fg.muted` ink-muted, `bg.subtle` surface, `border` muted rule, `border.ink` ink. Ink strips invert `fg`/`bg` and therefore follow palette and mode. `md` starts at **48rem / 768px**; `xl` at **80rem / 1280px**. Album/track cards use their **own 760px container width**, not the viewport breakpoint.

## Near-duplicates, conflicts and existing bugs

1. **Competing title scales.** Standard page h1 is 24px desktop; recap is 44px; album identity 30px; track identity 28px. Phone page bar is20px, album22px, track20px, recap30px. These are distinct systems, including two different responsive mechanisms.
2. **Duplicate page title / h1.** Track detail renders PageHeader h1 plus TrackHeader h1. Album repeats the title too, but uses h2 in the identity card. A redesign should decide the hierarchy, rather than copy the track pattern.
3. **Near-identical ink strips drift.** SectionHeading is26px, Home arrivals/playlists become24px on phones, NeedsAttention uses py4 with inherited30px line-height (38px total), genre strips use the configurable label face and .06em, most others fixed mono/.08em. Playlist month tabs are bold/.1em. Same section role, visibly different heights and tracking.
4. **Font-role conflict.** Changing Labels changes album counts, breadcrumbs, list controls and genre labels, but does not change Home/Spins/Chores fixed mono headings. Defaults conceal this conflict because both start with Plex Mono.
5. **Implicit 30px line-height on tiny headings.** Overlines and strips often override fontSize but not Heading's default text-style line-height. A 10–12px heading can still have a30px line box, including inside an explicitly24/26px wrapper. This is recorded, not corrected.
6. **Heading levels do not consistently encode the same tier.** DayHeading is h3; Chores overview h2; recap overline h3; settings nested subsections default h2. Generic md/sm defaults communicate size, not hierarchy. Accessible-only recap heading correctly exists despite having no visible specimen.
7. **Phone action layouts differ.** Standard PageHeader limits icon actions to two; richer trailing controls can still consume substantial width. Counts do not shrink and titles truncate. Home removes summary, detail replaces breadcrumbs, recap retains a separate breadcrumb bar and large title; Chores hides section labels and uses tabs. Consolidation must retain these different content priorities.
8. **Container width vs viewport.** Detail title size switches at760px of card width; the outer page bar switches at768px of viewport width. Sidebar/queue can leave a desktop route showing a narrow identity card beside a desktop title. The concurrent PageContainer width work may change available widths; this audit does not edit those files.
9. **Queue and spin identity are separate tiers.** QueueTitle18/24, phone track22/28 body face, spin panel17/22, TrackStripHeader16/22 display; all may describe a selected track. They should not silently become more page-header variants.

## Suggested consolidation — input for redesign, not a decision

No redesign or migration is implemented here. A possible four-page/two-section vocabulary:

| Suggested role    | Current groups it could replace    | Preserve explicitly                                                                                  |
| ----------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Page / list       | P1, P2, P3, P6, P7                 | Count vs summary, search, source tabs, two primary phone actions and overflow; desktop controls      |
| Detail            | P4                                 | Breadcrumb parent/back destination, menus, long titles                                               |
| Form              | P5                                 | Cancel/save, pending/disabled states, phone targets                                                  |
| Editorial         | P8                                 | Month navigation, separate phone title block                                                         |
| Section / display | S1, S2, S3, S6, S8, S16            | Semantic heading level, count, optional actions/subtitle; explicit line-height; ruled day metadata   |
| Section / label   | S4, S5, S7, S9, S11, S12, S13, S14 | One chosen font role and tracking scale; plain/ink/linked/tab context; phone visibility and dividers |

P9/P10 remain entity-identity compositions sharing typography with Detail; they need a deliberate semantic relationship with the page h1. S10 remains an accessibility technique. S15 and dialog titles can be reviewed separately. The proposal deliberately does not turn the audit's 16 section/reference groups into 16 new component variants.
